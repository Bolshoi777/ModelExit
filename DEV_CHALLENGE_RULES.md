# DEV Challenge — verified contest constraints (as of 2026-10-16)

## Authoritative URLs
- Challenge: https://dev.to/challenges/hacktoberfest-week2-2026-10-12
- Official contest rules: https://dev.to/page/hacktoberfest-week2-2026-10-12-contest-rules
- Submission template: click **Submission Template** from the challenge page. Use the latest official form, not a generic post.

## Calendar
Entry opens 2026-10-12 12:00 PDT; closes **2026-10-18 23:59 PDT**, equivalent to **2026-10-19 09:59 UTC+3**. This is a submission deadline, not just a code deadline. Aim for publication 2026-10-18 before 20:00 UTC+3.

## Required for eligible entry
- **New project** built during Oct 12–18 entry period.
- **Open-weight model and/or open-source AI tooling is a core functional element**, not a superficial label.
- Theme **Side Hustle**: realistic user/buyer who could pay for the solution.
- Published DEV post based on official **Submission Template** and unique challenge tag `hf26challenge` (template also includes `devchallenge`).
- Link to a deployed working project **or a real video demonstration**.
- Link/embed code repository.
- Explain why open innovation matters for this workload.
- **Only one entry for the week**; if multiple, only first is judged.

## Evaluation
1. Writing Quality — **weighted most heavily**.
2. Relevance to theme.
3. Creativity.
4. Technical Execution.
5. Partner technology, when claiming a partner prize.
A good article must narrate an **actual experiment and observed limits**, not market-speak and fabricated benchmarking.

## Prizes
- 1 overall prize: USD 250 + membership/badge.
- 6 featured technology awards: USD 200 each.
- 11 partner awards: USD 100 each.
- A submission can be considered for more than one category **but receive no more than one monetary prize**.
- **Best Use of Gemma** (USD 200 category): must actually use a Gemma model meaningfully; include actual model ID and show inference in demo. Not obligatory. Do not claim Gemma if using other weights.

## Optional first user / proof
Organizers explicitly encourage reporting actual user tests. Genuine feedback helps but is not compulsory. If no user tries it, write that plainly.

## Contest article requirements / exact template sections
- What I Built
- Demo
- Code
- How I Built It
- Why Does Open Innovation Matter?
- My Agent Session (optional)
- My First User (optional; omit if no user)
- Prize Categories (if entering partner categories)
Do not submit a bare GitHub README without a DEV post.

## Publication integrity
- Results must match app logs and screenshots; source samples identified synthetic.
- Cloud cost estimates are mathematical scenarios using clearly named assumptions, not real invoiced costs or side-by-side evaluated commercial AI unless measured.
- Partner credits are optional, do not spend money or promise credits.
- Verify eligibility under general Official Rules if necessary; this file does not replace legal rules.

# ModelExit — START HERE (RU)

## Цель
Создать за **48 часов с момента старта работы** работающий конкурсный MVP ModelExit для DEV Hacktoberfest 2026 Week 2 (Side Hustle). Проект совершенно отдельный от PortalGuard. AI-агент разработки: OpenCode. Код и UI ориентированы на Windows и локальный LM Studio, платные API не нужны.

**Сегодня 16 октября 2026 г.** Официальный крайний срок подачи — **18 октября 2026, 23:59 PDT = 19 октября 09:59 (UTC+3)**. Целевой внутренний срок: завершить публикацию **18 октября до 20:00 (UTC+3)** и оставить запас. 48 часов — лимит рабочего плана, а не разрешение пропустить официальный deadline.

## Что скачать/установить
- Python 3.11 или 3.12 (в PATH) и Git.
- OpenCode с настроенной **у тебя** моделью-агентом (эти документы не требуют платного API).
- LM Studio для выполнения *локальной* открытой/открыто-весовой модели внутри ModelExit.
- Модель, которая уже нормально запускается на твоём ПК: предпочтительно Gemma, если реально доступна (для конкурсной категории **Best Use of Gemma**). Не скачивать гигантскую модель без проверки ресурсов. Не заявлять категорию Gemma, если реально использовалась другая модель.

## Перед стартом OpenCode
1. Распакуй **в НОВУЮ папку**, например `C:\Projects\ModelExit` (не внутрь PortalGuard).
2. Открой папку в OpenCode. В корне лежит `AGENTS.md` — обязательные указания агенту.
3. В LM Studio загрузи локальную модель, открой **Developer → Start Server**, порт по умолчанию 1234.
4. Быстрая проверка в PowerShell:
   ```powershell
   Invoke-RestMethod http://localhost:1234/v1/models
   ```
   Если сервер недоступен, сначала включи его. Конкурсное демо обязано выполнить реальные вызовы модели, а не мок.
5. Создай **новый** GitHub-репозиторий для ModelExit; не используй репозиторий PortalGuard и не вставляй чужие API-ключи.
6. Отправь OpenCode промпт из `OPENCODE_PROMPTS.md` (Prompt A).

Для дополнительной проверки можно загрузить `samples/support_cases_extended.jsonl` через UI
или передать его в CLI с `--synthetic`. Это новый синтетический набор на 12 кейсов, а не реальные
клиентские данные и не часть уже опубликованных результатов. Такой прогон делает реальные вызовы
локальной модели и не нужен для повторения контрольных гейтов.

## Минимальное техническое обещание
**ModelExit:** приложение, которое прогоняет обращения службы поддержки через открытую локальную LLM, проверяет качество и пограничные ошибки и формирует честный паспорт пригодности для миграции с облачного AI. Не обещать полноценную автоматическую миграцию любого AI-приложения.

## Первая демонстрация
- Загрузить `samples/support_cases.jsonl`.
- Подключить реально загруженную модель LM Studio; показать ID модели.
- Запустить один конечный прогон (не более 12 запросов по умолчанию).
- Открыть результаты pass/fail, проваленные пограничные пары и честную рекомендацию `READY FOR PILOT / LIMITED PILOT / NOT READY`.
- Экспортировать `Exit Passport` в JSON и Markdown.
- Записать видео, продемонстрировать повторяемость запуска; написать английскую DEV-статью.

## Важнейшее ограничение на тесты
См. `TEST_POLICY.md`. **Не запускать тесты после каждого изменения.** Всего 3 контрольные проверки после крупных вех + один финальный ручной проход. Каждый gate максимум 2 прогона, без вечных retry/refactor-циклов. При сомнениях сначала завершать функционал, потом выполнять короткие критические проверки.

## Если на что-то не хватает времени
Приоритет: (1) настоящий AI-прогон (2) корректная проверка (3) видимые ошибки и рекомендации (4) export (5) видео/статья. Красивые анимации, генерация неограниченных тестов, SaaS-авторизация, облако, fine-tuning — НЕ делать.
